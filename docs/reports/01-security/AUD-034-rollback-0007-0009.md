## 3. Keputusan penting

1. **Urutan wajib terbalik:** `0009` → `0008` → `0007`. Objek batch berikutnya dapat bergantung pada unique parent dari batch sebelumnya.
2. **`kelompok_village_id_uq` tidak di-drop.** Unique itu berasal dari migration `0003`, bukan `0007`; menghapusnya akan merusak batch sebelumnya.
3. **Index pemulih tidak ditambahkan manual kecuali diperlukan.** Unique parent yang di-drop tetap tercakup index lain pada kolom `village_id` (`*_village_idx`, `*_village_code_unique`, `incoming_letters_village_received_idx`, dst.), sehingga FK CASCADE ke `villages` tidak gagal dengan errno 1553. Satu-satunya index yang dibuat ulang adalah `anggota_grup_kontak_kontak_id_kontak_id_fk` yang memang dibuat MySQL otomatis saat FK baseline dipasang kembali.
4. **Nama constraint dan rule dikembalikan persis seperti `0000_baseline.sql`**, sehingga `drizzle-kit` tidak melihat drift setelah rollback.
