# Laporan — CI Hanya pada Pull Request

- **Task:** Menghapus trigger CI `push` ke `main` agar test tidak berjalan dua kali
- **Tanggal:** 17 November 2026
- **Branch:** `task/ci-pr-only-2026-11-17`
- **Base commit:** `4ea7fd8d568a905f05e42f0f84fe45bf704e07f1` (`main`)
- **Commit perubahan:** `6e00ed122e3622d45ee5edffe8b4eea4f0d1a674`
- **Status:** siap review; CI PR diverifikasi setelah PR dibuat

## 1. Kondisi awal

`.github/workflows/ci.yml` memiliki dua trigger:

- `pull_request` ke `main` — menjadi required check branch protection;
- `push` ke `main` — menjalankan quality, integration, build, dan ringkasan lagi
  setelah PR di-merge.

Karena PR #95 sudah melewati seluruh required check sebelum merge, trigger push
menghasilkan pipeline kedua untuk commit yang sama. Ini membuang waktu CI tanpa
menambah gate baru.

## 2. Perubahan

- Menghapus blok `on.push` untuk `main`.
- Mempertahankan `on.pull_request` untuk semua PR ke `main`, termasuk PR
  dokumentasi, agar keempat required check selalu tersedia.
- Menyederhanakan concurrency group menjadi satu pipeline per nomor PR; commit
  baru pada PR yang sama membatalkan run lama.
- Branch protection tidak diubah: quality, integration MySQL, build, dan
  ringkasan tetap wajib sebelum merge.

## 4. Security dan tenant

dimatikan, direct push ke `main` tidak lagi memiliki CI pasca-merge.

## 6. Risiko

- Menghapus trigger push berarti tidak ada validasi tambahan pada commit merge.
  Ini diterima karena commit merge tidak mengubah kode dan PR sudah wajib lulus
  empat check.
- Jika branch protection dinonaktifkan, perubahan langsung ke `main` tidak akan
  menjalankan CI. Branch protection harus tetap aktif.
- Perubahan hanya pada workflow; job quality, integration, build, dan summary
  tidak diubah.

## 7. Kesimpulan

Trigger ganda dihapus tanpa mengurangi gate merge. Hasil CI PR dan verifikasi
bahwa merge tidak memicu workflow baru dicatat setelah PR dijalankan.
